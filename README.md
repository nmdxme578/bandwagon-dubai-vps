## 国内访问实测：延迟 350ms 起步，上传比下载快

先给结论：从国内访问迪拜机房，延迟 350–480ms，丢包偶发，下载速度一般；机房的 1Gbps 端口是真的，上传能跑满，瓶颈全在回程线路上。

从机房上线后的几轮公开测速看，国内三网平均延迟大致是这个水平：

| 线路 | 平均延迟 | 实测区间 |
| --- | --- | --- |
| 电信 | 360–390ms | 最快约 300ms，最慢超过 420ms |
| 联通 | 380–430ms | 个别节点超过 480ms |
| 移动 | 350–360ms | 三家里相对最稳 |

延迟高的原因看回程路由就明白了，三条线路全绕路：

- **电信**：经 HE 线路从迪拜出发，过法国马赛、英国伦敦，再接电信国际入口回国，绕了大半个地球
- **联通**：迪拜 → 新加坡 → 东京 → 洛杉矶 → 联通骨干回国，绕道美西再折返
- **移动**：经 i3d 线路过米兰、苏黎世、法兰克福，从中国移动欧洲入口回国

阿联酋到中国的物理距离摆在那，又没走 CN2 这类优化路由，这个延迟是地理和线路共同决定的，跟机房本身关系不大。丢包方面大部分节点 0%，北京、成都方向的联通节点偶尔出现 20%–40% 的抖动。

速度数据里有个反常识的点：上传比下载猛。三网上传都能跑到 800Mbps 以上，基本吃满 1Gbps 端口；下载在国内只有 150Mbps 上下。端口带宽没虚标，慢是回程线路的问题。硬盘 IO 成绩在 700MB/s 上下，RAID-10 的正常水准，跑数据库、建站都够用。
